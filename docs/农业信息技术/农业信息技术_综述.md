# 基于大语言模型的农业知识图谱自动构建：从联合抽取到 Agentic 服务的演进路径与技术边界

## 摘要

农业知识图谱的构建正经历从"实验室探索"到"工程化落地"的关键转折。本文梳理了 2024 至 2026 年初的技术演进脉络：早期以实体-关系联合抽取与 LoRA 微调为核心（准确率可达 87.04%），2025 年底出现了递进提示抽取（PPE）与增量实体更新（IEU）等精细化流程，检索架构则从传统 RAG 升级为 AgenticGraphRAG（ReAct + 双检索 + RRF 融合）。与此同时，Model Context Protocol（MCP）协议的标准化（200+ 社区服务器）为知识图谱的工程集成提供了新范式，但也引入了 MCPThreatHive 框架所揭示的 38 种安全威胁模式，这在农业等垂直领域的适配尚未完成。

本文以小麦纹枯病防治知识图谱为案例，保留原始实测数据（ERNIE 3.0 / GLM-4-9B，篇章级抽取准确率 87.04%），同时指出当前单点技术向系统化服务转化时必须补全的环节：渐进式 Cypher 生成容错、增量知识维护协议、多模态融合的具体实现路径（如 YOLOv8+RAG 咖啡病害诊断），以及 MCP 安全层的领域化部署。结论强调：农业 KG 的成熟不取决于单一模型的性能提升，而取决于全生命周期管道的可观测性、可回滚性与专家闭环机制。

**关键词**：大语言模型；农业知识图谱；递进提示抽取；AgenticGraphRAG；MCP 协议；增量实体更新；人机协同验证

---

## 一、研究进展：从手工构建到 Agentic 全生命周期管理

### 1.1 实体与关系抽取的范式演进

传统农业 KG 构建遵循"先命名实体识别（NER），后关系抽取（RE）"的级联范式，流程割裂且标注成本高。2024 年的核心突破是利用大语言模型的上下文理解能力进行实体-关系联合抽取，通过设计领域特定的提示词模板，直接从非结构化文本中输出三元组，并配合 LoRA 高效微调降低计算门槛。至 2025 年底，上海海洋大学的研究团队提出了更精细化的递进提示抽取（Progressive Prompt Extraction, PPE）与增量实体更新（Incremental Entity Update, IEU）机制。

PPE 将抽取任务分解为三阶段轮询：首轮识别核心实体，次轮建立实体间关系假设，末轮验证并修正边界冲突。IEU 则区分"主属性"（来自结构化数据库的高可信数据）与"次属性"（从新抽取文本中获得的数据），在冲突时优先保留主属性，从而支持知识图谱的增量维护而非全量重建。

实验表明，在农业场景下，Qwen2.5-32B 配合 PPE 的实体属性抽取 F1 可达 **85.1%**，三元组抽取 F1 达 **81.4%**，超过同模型无 PPE 的基线（77.9% / 76.6%），验证了"小模型配合优化流程可超越裸大模型"的工程结论。

### 1.2 检索增强的架构升级：从 RAG 到 AgenticGraphRAG

将知识图谱作为 LLM 的外部知识库以缓解"幻觉"问题，已成为农业智能问答的直接应用路径。然而，传统 RAG 在处理农业复杂查询时存在局限：当农民询问"我家小麦叶子发黄怎么办"时，单一检索策略难以同时覆盖症状语义匹配（"发黄"）与结构化条件过滤（作物类型、生长期、地域）。

2025 年底提出的 AgenticGraphRAG 架构引入了 **ReAct（Reasoning + Acting）** 规划机制：LLM 不再直接生成答案，而是将问题分解为子任务（症状识别→病害候选→防治方案检索），自主决策调用向量检索（语义模糊时）或 Cypher 结构化检索（条件明确时），并通过倒数排序融合（RRF）合并多源结果。该架构在水稻领域的人工查询诊断中达到 **86%** 准确率，LLM 模拟查询达 **89.33%**。

> ⚠️ 当前农业 KG 问答研究已要求与 NaiveRAG、GraphRAG、LightRAG、HippoRAG2 等基线进行严格对比，否则不具备方法层面的可比性。

### 1.3 工程集成层：MCP 协议的标准化与安全债务

2024 年底 Anthropic 开源 MCP 协议后，截至 2026 年 3 月已有超过 **200 个** 社区 MCP 服务器，被 Claude、Cursor、Zed 等工具原生支持。知识图谱领域出现了 Neo4j 官方 MCP 套件（mcp-neo4j-cypher、mcp-neo4j-memory）及学术论文实现的 SPARQL-MCP 联邦查询接口，为 KG 与 LLM 的集成提供了标准化管道。

然而，2026 年 4 月初发布的 MCPThreatHive 研究框架指出，MCP 引入了 **38 种** 特定威胁模式（工具描述投毒、间接提示注入、寄生工具链），现有 OWASP 安全框架无法完全覆盖。对于农业知识服务这类涉及生产决策的场景，MCP 集成的工具执行审批、上下文隔离与权限粒度控制成为应作为设计约束的工程环节，而非可选增强。

## 二、应用现状：从实验室到田间

### 2.1 智能问答与农业咨询

将知识图谱作为 LLM 的外部知识库，可有效缓解 LLM 的"幻觉"问题。当农民询问"我家小麦叶子发黄怎么办"时，系统先通过知识图谱检索到"小麦-症状-叶黄"的可能原因（如缺氮、纹枯病或干旱），再由 LLM 组织成通俗易懂的回答。AgenticGraphRAG 架构进一步将这一过程分解为可观测的子步骤，使错误定位从"答案错误"细化到"检索策略选择错误"或"Cypher 生成错误"。

### 2.2 农作物病虫害诊断辅助

通过整合植保手册、论文和专家经验构建的知识图谱，LLM 能够根据用户描述的症状推理最可能的病害并提供防治建议。2025 年的具体实现案例包括：基于 YOLOv8 检测咖啡病叶后，通过 RAG 增强 LLM 生成防治建议的端到端系统；以及基于 InternVL2-8B 多模态大模型，结合 SFT、RAG 与 RLHF 构建的小麦育种助手，在品种选择与表型分析任务上实现了视觉-文本联合推理。

### 2.3 多模态农业知识图谱：从趋势到具象

"多模态知识图谱"已不再是趋势预测，而是有了具体实现。**VEG-MMKG** 项目基于预训练模型从图像、文本、视频、音频中抽取多模态知识构建蔬菜领域 KG；水稻与小麦领域的研究则探索了表型图像与文本描述的联合索引。这些实践表明，农业 KG 的下一步扩展需明确回答：当文本抽取置信度与视觉分类置信度冲突时，系统应遵循何种加权投票或专家仲裁协议。

## 三、案例分析：小麦纹枯病防治知识图谱的构建实践

> 本节基于刘珂艺（2024.12）的研究，保留原始实测数据，同时指出其向 2026 年工程标准演进时的补全空间。

### 3.1 知识抽取阶段：从联合抽取到递进优化

原始研究基于 ERNIE 3.0 和 GLM-4-9B 预训练模型，通过有监督微调和 LoRA 技术，构建了面向小麦纹枯病领域的实体关系联合抽取模型与防治措施分类模型，篇章级知识自动抽取准确率达 **87.04%**。这一数据反映了 2024-2025 年初联合抽取范式的典型性能水平。

若引入 2025 年底的 PPE 方法，该案例可进一步优化：将"症状-病害-防治"的长文本描述分解为多轮抽取，每轮聚焦单一语义角色，降低跨句子信息处理的错误传播。但需注意：87.04% 为**准确率（Accuracy）**，非 F1-score，二者在类别不平衡的农业语料中存在差异，未来研究应补充 F1、精确率、召回率及错误分布（边界错误、关系方向错误、幻觉实体占比）的完整报告。

### 3.2 知识服务阶段：Cypher 查询与渐进式生成

原始研究中，LLM 被用于将自然语言问题自动转换为 Cypher 图数据库查询语句，实现精准语义解析。2026 年的工程实践要求补充渐进式生成与语法容错机制：当 LLM 生成的 Cypher 存在语法错误（如缺少 RETURN 子句）时，系统应进入修复模式（至多 3 次重试），失败后降级为向量检索 + 生成摘要的 RAG 模式，确保服务不中断。此外，每个回答应附带**溯源链路（Provenance Tracking）**，标明实体来源的 PDF 页码、段落 ID 及抽取置信度，以建立农户信任。

### 3.3 知识维护阶段：增量更新与专家闭环（新增）

原始研究未涉及知识图谱的持续维护。2025 年底的 IEU 机制为此提供了参考：当新的农技手册或政策文本（如农药禁用公告）接入时，系统仅抽取新增实体与关系，并与现有图谱中的"主属性"进行冲突检测。若检测到矛盾（如某农药从"推荐"变为"禁用"），生成冲突报告推送专家仲裁，而非自动覆盖。专家修正结果以增量样本形式反馈至微调模块，避免全量重训的成本。

## 四、现存问题：理想与现实的结构性差距

### 4.1 农业知识的复杂性与专业性

农业知识具有强烈的地域性、时效性和情境依赖性。同一品种在不同气候、土壤下的表现可能完全不同。LLM 难以捕捉这些细微差异，容易生成"听起来正确但实际不适用"的结论。AgenticGraphRAG 通过 ReAct 分解可在一定程度上缓解此问题（如将地域、生长期作为结构化过滤条件），但无法替代专家对于边缘案例的最终裁决。

### 4.2 数据获取与更新的工程挑战

尽管 LLM 降低了标注成本，高质量农业领域语料仍然稀缺且分散。农情变化快（如气候异常年份的病害爆发模式），知识更新时效性不足。IEU 机制虽支持增量维护，但其 Token 消耗与构建时间需纳入成本评估（据上海海洋大学水稻 KG 构建实验：构建 **901 实体**、**1,554 三元组**的 KG 消耗约 **300 万 Tokens**，耗时 **3.38 小时**，Qwen2.5-72B）。对于普通农业企业，这仍是需精打细算的资源投入。

### 4.3 计算资源与部署门槛

部署高性能 LLM 需要较强计算资源。2025 年的研究表明，Qwen2.5-32B 配合 PPE 可在性能上逼近 72B 裸模型，为边缘部署提供了模型尺寸与流程复杂度的权衡空间。基层农技站可采用更小规模的本地模型（如 1.5B-7B）处理高频常见查询，仅在置信度低于阈值时通过 MCP 协议调用云端大模型作为 Fallback。

### 4.4 MCP 集成的安全约束（2026 新增）

将知识图谱服务通过 MCP 协议接入 LLM Agent 生态时，必须正视 MCPThreatHive 揭示的风险：工具描述投毒可能导致 LLM 调用错误的图谱查询接口；间接提示注入可能篡改 Cypher 生成逻辑。农业场景涉及农药推荐、病害诊断等高风险决策，工具执行审批（Manual Approval）与上下文隔离不应被视为性能损耗，而是安全刚需。

## 五、发展趋势：可信、轻量、协同

### 5.1 轻量化与领域适配

未来该领域将趋向通过微调小规模 LLM 降低应用门槛。核心认知已从"追求最大模型"转向"优化流程设计"：32B 模型配合 PPE 超越 72B 裸模型的实证，证明了农业 KG 构建的流程工程价值不亚于模型工程。

### 5.2 人机协同的交互式验证

专家便捷校验并持续优化模型仍是关键。建议构建的闭环包括：错误标记（农技人员选择错误类型）→ 增量修正（50–100 条样本更新 LoRA，约 15 分钟）→ 版本回滚（验证集 F1 下降时自动恢复上一版本）。这一机制借鉴了软件工程中的原子更新与回滚原则。

### 5.3 多模态知识图谱的具象路径

融合图像、遥感与传感器数据已成为具体工程目标而非远景。可行路径包括：无人机影像经 YOLO 检测病斑 → 提取病斑特征向量 → 与文本 KG 中的病害节点建立跨模态边 → LLM 联合生成诊断报告。此过程需显式定义模态间冲突消解协议（如视觉置信度优先于文本抽取置信度，或差异超过阈值时触发人工仲裁）。

### 5.4 可解释性与安全增强

LLM 需能追溯知识来源，让结论"有据可依"。同时，MCP 协议在农业 KG 中的部署需配套安全层：工具描述的数字签名验证、Cypher 查询的语法沙箱执行、敏感操作（如农药剂量推荐）的人工确认节点。

## 结论

基于大语言模型的农业知识图谱自动构建，正处于从"单点技术验证"走向"系统化工程落地"的关键阶段。技术演进的时间线清晰可辨：2024–2025 上半年以联合抽取 + LoRA 为核心；2025 年底出现了 PPE/IEU 等精细化流程与 AgenticGraphRAG 检索架构；2026 年初 MCP 协议为工程集成提供了标准化接口，但也带来了 38 种新型安全威胁的适配挑战。

它极大地提升了知识工程的效率，让智能化的农业知识服务成为可能。然而，农业知识的独特性和 LLM 本身固有的缺陷，决定了当前技术尚不能完全取代人工。未来，以流程优化降低模型依赖、以增量更新替代全量重建、以 Agentic 分解提升复杂查询处理能力、以 MCP 安全层保障服务可信性，将是该领域走向成熟的关键。对于农业信息化建设而言，理性认识 LLM 的能力边界——特别是区分"模型存在"、"方法验证"与"工程成熟"三个层级——选择合适的技术路径，比盲目追求全自动更为重要。
